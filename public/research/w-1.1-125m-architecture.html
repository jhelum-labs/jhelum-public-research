1. Executive Design Summary

W-1.1-125M is a modern, decoder-only autoregressive Transformer designed to be trained from scratch. It keeps the model small enough for an independent research project while using current architectural choices that make training and inference efficient: RoPE positional encoding, RMSNorm, SwiGLU feed-forward layers, causal self-attention, tied token embeddings, BF16 training, Flash-Attention compatibility, and KV caching.

2. Exact Model Architecture

2.0 Why this model uses 14 layers

The 14-layer depth is a deliberate parameter-allocation choice. With a 32,000-token vocabulary, tied embeddings consume 24.58M parameters. Fourteen 768-wide blocks with a 2,048-wide SwiGLU MLP use the remaining budget efficiently and produce a 123.69M-parameter model without enlarging the vocabulary or introducing arbitrary dimensions. A 12-layer version with the same widths would be about 109.53M parameters, materially below the target class. The 14-layer choice must still be validated through training stability and quality measurements; it is a design rationale, not a claim of superiority over every 12-layer alternative.

2.1 Input and token embedding

  • Input is a batch of integer token IDs with shape [batch, sequence_length].
  • A learned token embedding matrix maps each token ID to a 768-dimensional vector.
  • Embedding matrix shape: 32,000 × 768 = 24,576,000 parameters.
  • No learned absolute positional embedding is used; position information is introduced inside attention through RoPE.
  • Embedding and output LM-head weights are tied, so the same 32,000 × 768 matrix is reused for output logits.

2.2 Transformer block × 14

Every block uses pre-normalization. The block order is frozen as follows:

  1. RMSNorm on the residual stream
  2. Causal multi-head self-attention with RoPE
  3. Residual addition
  4. RMSNorm
  5. SwiGLU MLP
  6. Residual addition

This ordering improves training stability and keeps the residual path clean. The implementation should use residual additions in FP32 when practical, while the main matrix multiplications run in BF16 on supported GPUs.

For each position, attention is computed from Q, K, and V. The scale factor is 1/√64 = 1/8 before the softmax. RoPE is applied to Q and K. Padding must be handled by the data pipeline or an explicit attention mask when batches contain padding.

2.4 Rotary positional encoding (RoPE)

  • RoPE dimension: full 64 dimensions of each attention head.
  • Base theta: 10,000 for the frozen v1 baseline.
  • Maximum trained context: 2,048 tokens. Longer context is a future extension and should be evaluated rather than assumed to work.
  • Cache RoPE sin/cos or equivalent frequency tensors to avoid recomputing them every forward pass.

2.5 RMSNorm

  • RMSNorm before attention and before the MLP in every block, plus one final RMSNorm after block 14.
  • Normalization width: 768. Use epsilon = 1e-5.
  • RMSNorm has a learned scale vector and no learned bias.

The MLP computes SiLU(gate(x)) ⊙ up(x), then projects the result back to 768 dimensions. Linear layers are bias-free in the frozen design.

2.7 Final norm and language-model head

  • Apply final RMSNorm to the output of the last Transformer block.
  • Project 768-dimensional states to 32,000 vocabulary logits using the transposed token-embedding matrix.
  • Use cross-entropy loss against the next token. Shift inputs and targets by one position; ignore masked/padding positions if any exist.

  • Total tokens: 5.0B, equal to about 40 training tokens per model parameter.
  • Approximate clean UTF-8 text footprint: about 20–30 GB, strongly dependent on language mix and tokenizer efficiency.
  • Packed token IDs occupy about 10 GB as uint16 (32K vocabulary fits in 16 bits), or about 20 GB as int32, before indexes/metadata.
  • Keep train, validation, and test documents separated before packing to reduce leakage.
  • The 5.0B figure means tokens actually consumed from the training split. Validation and test tokens are additional and never count toward the optimization budget.
  • Create document-level held-out sets before packing: target at least 10M validation tokens and 10M test tokens, stratified by language and domain where volume permits.

6. Data Processing Pipeline

  1. Acquire only permitted datasets and record source/license metadata.
  2. Normalize encoding and remove broken/corrupt records while preserving meaningful Unicode.
  3. Apply language and quality filtering.
  4. Remove exact duplicates and perform near-duplicate/document-level deduplication.
  5. Remove obvious secrets, credential dumps, personally identifying data where feasible, spam, and low-quality boilerplate.
  6. Split documents into train/validation/test before sequence packing.
  7. Train/freeze the 32K byte-level BPE tokenizer on a representative sample.
  8. Tokenize documents and append EOS/document boundary tokens.
  9. Pack token streams into 2,048-token training sequences without silently mixing validation/test data.
  10. Save deterministic shards plus manifest, checksums, counts, and tokenizer version.

These values define the frozen full-run recipe. First run a separate 50–200-step pilot that does not count toward the 5B-token run. It must verify stable loss, finite gradients, checkpoint/resume equivalence, memory headroom and adequate input throughput. Gradient accumulation and data parallelism may change, but their product must preserve the 524,288-token global batch.

8. Training Runtime and Efficiency

  • Use PyTorch DistributedDataParallel for multi-GPU training; use FSDP only if required by memory scale.
  • Use scaled-dot-product attention / Flash-Attention kernels where supported.
  • Enable gradient checkpointing only when memory pressure justifies the extra compute.
  • Use fused AdamW and fused normalization/activation kernels when stable on the target stack.
  • Pre-tokenize and memory-map/shard data so GPU training is not starved by text processing.
  • Log tokens/second, model FLOP utilization where available, training/validation loss, LR, gradient norm, GPU memory, and checkpoint IDs.

9. Checkpoints and Reproducibility

  • Checkpoint model weights, optimizer state, scheduler state, scaler state if used, global step, tokens seen, and RNG states.
  • Store architecture config and tokenizer files beside checkpoints.
  • Record dataset manifest/version, shard checksums, source proportions, git commit, package versions, and training command/config.
  • Resume must reproduce the data position or use a documented resampling policy.
  • Save weights in safetensors for distribution when possible; training-state checkpoints may use framework-native formats.

11. Post-Training: Turning the Base Model into a Chat Model

Pretraining produces a base next-token model, not a polished assistant. Chat behavior should be added as a separate, versioned stage so the original base model remains available.

  1. Supervised instruction tuning on a carefully licensed, high-quality conversation/instruction dataset.
  2. Define a stable chat template and reserve/version any required control tokens.
  3. Run safety and refusal-behavior evaluation appropriate to the deployment domain.
  4. Optionally run preference optimization after supervised tuning if a trustworthy preference dataset and evaluation suite are available.
  5. Re-evaluate general-language quality to detect catastrophic degradation from post-training.

15. Definition of “Production Ready” for This Project

  • Architecture is configuration-driven and parameter count is unit-tested.
  • Tokenizer is frozen, versioned and packaged with every checkpoint.
  • Dataset pipeline is reproducible, deduplicated, split safely, and source/licensing metadata is retained.
  • Training can resume from checkpoint without corrupting optimizer or data state.
  • Automated tests cover tensor shapes, masking, RoPE, weight tying, generation cache, serialization and a tiny overfit run.
  • Evaluation is run on held-out data before and after post-training.
  • Inference enforces context/output limits and exposes health/metrics endpoints.
  • Quantized builds are released only after comparing quality against the reference precision model.
  • A model card documents architecture, data categories, intended use, limitations, evaluation results and license information.

16. Final Frozen Blueprint

32K BPE tokens → 768-d embeddings → 14 × [RMSNorm → 12-head causal MHA + RoPE → residual → RMSNorm → 2,048-d SwiGLU → residual] → final RMSNorm → tied 32K LM head → next-token logits

Training target: 5 billion tokens at a maximum sequence length of 2,048. The result is the W-1.1-125M base model (~123.69M trainable parameters), after which instruction tuning and deployment are separate, versioned stages.

17. Architecture Freeze Checklist

  • 14 layers / 768 width / 12 heads / 64 head dimension
  • 2,048 SwiGLU hidden size
  • 32,000 byte-level BPE vocabulary
  • 2,048-token trained context
  • RoPE θ = 10,000
  • RMSNorm ε = 1e-5
  • Bias-free linear layers
  • Tied input/output embeddings
  • 5B-token pretraining target
  • BF16-first training
  • AdamW + warmup + cosine schedule
  • KV-cache inference
  • Base checkpoint preserved before chat post-training
